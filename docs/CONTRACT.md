# Basira Financial X-ray implementation contract

Product working name: بصيرة / Basira. Independent software project; do not edit parent NexusPay app. Arabic-first, RTL, English UI toggle. Real persisted data and authenticated server-side permissions. Local implementation can use SQLite; production database adapter should support PostgreSQL. No claim of production certification or best-in-world validation.

## Engine interface

Python `engine/cli.py` reads ONE JSON object on stdin, prints ONE JSON object on stdout (diagnostic errors stderr), exits nonzero on failure. Supported operations:

- `{op:"extract",path:absoluteServerOwnedPath,filename:"original.xlsx",currency:"SAR",scale?:1000}` -> `{facts,periods,warnings,source_preview,document_type,requires_manual_mapping}`.
- `{op:"analyze",facts,settings:{days:365,include_leases:true,materiality_pct:1}}` -> `{engine_version,periods,metrics,findings,checks}`.
- `{op:"scenario",facts,scenario:{type:"collection_days"|"gross_margin"|"opex_reduction"|"financing_rate"|"contract_assets",low:number,base:number,high:number,financing_rate?:number,implementation_cost?:number}}` -> `{type,effect_type,low,base,high,currency,unit,formula,source_refs,assumptions_ar,assumptions_en,dependency_group}`.

Fact: `{id,concept,label_ar,label_en,period:"2025",value:number|null,currency:"SAR",unit:"currency"|"percent"|"days"|"number",scale:1000,original_value:number|null,source:{sheet?:string,cell?:string,page?:number,bbox?:number[]},formula?:string,cache_status?:string,review_status:"needs_review"|"reviewed",scope:"consolidated"}`. Values normalize to full currency units, not millions. Missing != zero. Keep raw signed/text/source provenance. Recommended concept names include revenue,cogs,gross_profit,ebit,net_income,cfo,cash,deposits,receivables,contract_assets,current_assets,current_liabilities,total_assets,total_liabilities,equity,borrowing_current,borrowing_noncurrent,lease_current,lease_noncurrent,finance_cost,depreciation_amortization,sga,gna,capex,inventory,trade_payables,credit_sales,purchases,ar_allowance,gross_receivables.

Metric: `{id:"gross_margin:2025",key:"gross_margin",period,label_ar,label_en,value:number|null,unit:"currency"|"percent"|"days"|"multiple",status:"ok"|"proxy"|"not_applicable"|"insufficient_data"|"invalid_denominator",formula,inputs:string[],explanation_ar,explanation_en,group:"growth"|"profitability"|"cash"|"liquidity"|"working_capital"|"funding"|"returns"}`. Percent values are 0–100. Negative values preserved. Optional `prior_value`, `delta`.

Finding: `{id,rule_id,title_ar,title_en,summary_ar,summary_en,severity:"high"|"medium"|"low"|"info",kind:"risk"|"opportunity"|"data_quality",evidence_status:"supported"|"hypothesis"|"needs_data",metric_ids:string[],source_refs:string[],questions_ar:string[],questions_en:string[],action_ar,action_en}`. Never accuse fraud/distress from ratios alone. Checks: `{id,label_ar,label_en,status:"pass"|"fail"|"warning",difference?:number,tolerance?:number,details_ar,details_en}`.

## HTTP API /api

Same-origin httpOnly session cookie, CSRF header `X-CSRF-Token` on all authenticated mutations; token returned by session. JSON requests and JSON responses except document downloads/report exports. Error `{error:{code,message,message_ar,details?}}`. All lists plain arrays unless described. All entities server tenant-scoped. Timestamps ISO. IDs UUIDs. Numeric persisted revisions required for edits.

- GET /health, GET /session -> `{user:{id,name,email,role},tenant:{id,name,demo},csrfToken,capabilities}` or401.
- POST /auth/register `{name,email,password,company}` -> session. POST /auth/login `{email,password}` -> session. POST /auth/logout.
- POST /auth/demo `{role?:"cfo"|"analyst"|"operator"|"board"}` -> session in isolated demo tenant; only demo role switching, never real-tenant elevation. Disable demo in production unless expressly enabled. Root UI offers one-click sample workspace and explicit demo role control.
- GET /entities; POST /entities `{name,sector,currency,sector_code?}` (`sector_code` optional, one of `it_services|commercial_services|transport_logistics|other` — a controlled vocabulary used for peer-eligibility matching alongside the free-text `sector`); GET /members.
- GET /dashboard?entity_id=... -> `{entity,entities,dataset,analysis,actions,documents,notifications}`. latest analysis may be draft; clearly labeled. dataset null supported.
- POST /demo/seed -> loads Elm reference via engine into current demo tenant only; repeat idempotent, no fabricated peer data or actual-saving claims.
- GET /documents?entity_id=; POST /documents `{entity_id,filename,content_base64,rights_confirmed:true,currency?,scale?}` ->202 `{document,job_id}`. Limit original10MB; safe server-owned path; never execute macros/external refs. GET /jobs/:id; GET /documents/:id/content; DELETE /documents/:id (retention/archive rules).
- GET /datasets?entity_id=; GET /datasets/:id -> `{id,entity_id,document_id,status,version,facts,periods,warnings,source_preview,checks,created_by}`.
- PATCH /datasets/:id/facts/:factId `{version,value?,concept?,review_status?,reason}`; POST /datasets/:id/approve `{version}` separate authorized reviewer, block material failed checks. POST /datasets/:id/analyze -> analysis.
- GET /analyses/:id; POST /findings/:analysisId/:findingId/review `{status:"accepted"|"rejected"|"needs_data",reason}`. persisted reviews included in analysis.finding_reviews.
- POST /scenarios/evaluate `{dataset_id,type,low,base,high,financing_rate?,implementation_cost?}`; POST /scenarios/save same + title; GET /scenarios?entity_id=.
- GET /peers?entity_id=; POST /peers `{entity_id,name,sector,country,currency,period,source_url,rights_basis,metrics:Record<string,number>,definition_notes,sector_code?}` (same optional controlled vocabulary as entities); POST /benchmarks `{entity_id,metric_key,peer_ids:string[],period?}` -> `{id,metric_key,company_value,n,median,q1,q3,rank?:number,eligible,exclusions,warnings,peers}`. `period` is optional and must be one of the entity's own analyzed periods; defaults to the latest. Sector eligibility uses `sector_code` when both the entity and peer carry one (exact free-text `sector` equality otherwise, unchanged) — real peer filings almost never match a free-text sector description verbatim even when genuinely comparable. Using a non-latest `period` is disclosed in the snapshot's `warnings`, never silent. No fake external benchmarks. Immutable snapshots; cohort eligibility and minimum samples.
- GET /actions?entity_id=; POST /actions `{entity_id,analysis_id?,finding_id?,title,description,owner_id,due_date,baseline,target,unit,effect_type,dependency_group?}` -> action. PATCH /actions/:id `{version,...editableFields,reason}`. POST /actions/:id/transition `{version,status,reason}`; states draft,approved,in_progress,blocked,pending_verification,closed,benefit_verified,reopened. Enforce valid transitions/permissions, evidence and independent verification. POST /actions/:id/evidence `{title,note,filename?,content_base64?}`. POST /actions/:id/benefit `{baseline,actual,amount,effect_type,period_start,period_end,method,confounders}` CFO independent approval. GET /actions/:id ->full evidence/history. Overlap protection.
- GET /reports?entity_id=; POST /reports `{entity_id,analysis_id,title,language:"ar"|"en"}` ->draft frozen snapshot. GET /reports/:id; POST /reports/:id/approve ->immutable approved snapshot, separation of duties and dataset-approved gate. GET /reports/:id/export?format=html|json. Board cannot read drafts/raw sources.
- POST /assistant `{entity_id,question,report_id?}` -> `{answer,mode:"evidence"|"llm",citations:[{label,fact_id?,metric_id?,source?}],limitations}`. Permission-scoped, abstain when not known; no invented LLM mode. Optional external provider only if configured; no browser/client API keys.
- GET /audit; GET /notifications; POST /notifications/:id/read.
- GET /settings -> policies; PATCH /settings `{materiality_pct,include_leases,days,retention_days,locale,...}` role-check/version audit.
- GET /capabilities -> exact integration/OCR/AI/storage capability states. Additional member management, forecast, connectors, portfolio may follow without breaking above.

Frontend API conventions: fetch wrapper includes CSRF, credentials same-origin, AbortController, display safe errors; query keys include entity; refresh after mutations. No mock data masquerading as live; sample is labeled. API requests need no localStorage auth. LocalStorage only theme/locale preferences. Actions/report edits need version.

All source must be buildable independently via manifest. Test financial/security rules first; end-to-end browser QA on actual API, real upload, separate reviewer, approved report and source drilldown. No public deployment or external messages during development. Design is navy/teal, light workspace, restrained dense financial tables, accessible native/Radix interactions, 16px body, visible focus, mobile/200% zoom.
